# Как внести изменение

Процесс TeamFinder: Issue → Assignee → Branch → Commits → Pull Request → Review → Merge → Done.

1. Выберите Issue в нужном репозитории и назначьте исполнителя на [доске](https://github.com/orgs/TeamFinderProject/projects/1).
2. Создайте ветку от актуального develop: feature/…, fix/… или docs/…. Для репозитория .github исходная ветка — main.
3. Вносите связанные изменения понятными коммитами. Не добавляйте .env, токены и результаты локальной сборки.
4. Откройте PR в исходную ветку. Опишите изменение, способ проверки и результат. Ссылкой Closes завершайте только полностью выполненную Issue.
5. Второй участник проводит review. Для backend и frontend дождитесь обязательного CI.
6. После merge обновите статус задачи. Слияние PR и завершение всей Issue могут быть разными шагами.

Изменения API согласуйте с [контрактом](https://github.com/TeamFinderProject/teamfinder-docs/blob/develop/api-contracts-v1.md). Правила и инструкции запуска обновляйте вместе с кодом. Авторство существующих коммитов сохраняйте; не выдавайте непроверенный сценарий за проверенный.
